Deception grid for AI agents

Decoy agents that record what attackers ask of them, and never do it.

Tripvane runs decoy AI agents on the open internet. When someone tries to steer one with a prompt injection, every tool call it attempts is recorded and answered with a fake result. Nothing runs, and what the decoys capture becomes a public lookup.

How it works

From one injected message to a public record

Six stages, each one written down in the open-source code.

  1. 1Decoy receives inputinput_received
  2. 2Cheap checkgate · budget · rate limit
  3. 3Attempt recordedtool_call_attempted
  4. 4CollectorPOST /ingest
  5. 5Analystgate · tagger · campaigns
  6. 6PublishedGET /v1/lookup
  1. Stage 1

    A decoy receives input

    Each decoy looks like an ordinary agent product with ordinary tools: send_email, read_file, list_secrets, run_shell, http_get and write_file, plus a few that fit its role.

  2. Stage 2

    A cheap check runs first

    Input under eight characters, or a repeat of a recently accepted payload, never reaches a model. Each decoy has a daily token budget and a per-address rate limit, so a scanner cannot run up the bill.

  3. Stage 3

    Tool calls are recorded, never run

    Every call becomes a tool_call_attempted event with its arguments and the static fake result the model was shown. Credentials planted in those results are canaries: realistic in shape and invalid everywhere.

  4. Stage 4

    Events reach the collector

    Each event is written to disk on the decoy before it is shipped to an authenticated ingest endpoint, and it stays there until the collector accepts it.

  5. Stage 5

    The analyst classifies

    A small model decides whether an input tries to make an agent act against its operator. Attacks are tagged on three axes, and near-identical payloads are grouped into campaigns.

  6. Stage 6

    Results are published

    A public lookup API and page, a feed for key holders, a Claude Code plugin, and a weekly brief that a person reviews before it goes out.

Lookup

Has the grid seen it?

Try

Enter an IPv4 or IPv6 address, a domain, or the sha256 of a payload. The answer gives first and last sighting, how many decoys and sessions saw it, its most common tags and its campaign.

Not seen is not a clean bill of health. It means only that this grid has not recorded the value. New hosts and reworded text are unseen by definition.

Payloads are looked up by hash, so the text never has to leave your machine. The hash is taken after lowercasing, collapsing every run of whitespace to one space and trimming both ends.

Lookups are free: 50 a day per address, or 5,000 a day with an API key. Full lookup page · API reference

For developers

Plain JSON, and a plugin for your agent

API and feed

The lookups are public. The feed returns attack payloads from the last 24 hours with their tags and campaign ids, and needs a key sent as X-Api-Key. Keys are issued by hand while the grid is young; ask for one through the repository.

# public, 50 a day per address
GET /v1/lookup/ip/{ip}
GET /v1/lookup/domain/{domain}
GET /v1/lookup/payload/{sha256}

# with X-Api-Key, 5,000 a day
GET /v1/feed/recent

Claude Code plugin

Three lookup tools and a skill that tells Claude when to use them: before installing an MCP server from a host it has not seen, and whenever a document, issue or web page reads as instructions aimed at an agent. It sends only the value being looked up; for text, that is the hash.

/plugin marketplace add TanmayKallakuri/TripVane
/plugin install tripvane@tripvane
claude plugin marketplace add TanmayKallakuri/TripVane
claude plugin install tripvane@tripvane

When asked for the API URL, enter https://tripvane-api.vercel.app. An API key is optional. The plugin needs uv on your PATH.

Weekly brief

What the grid saw this week, checked by a person

Each week a model drafts a short brief from the period's aggregate figures. It never sees captured payload text, so nothing an attacker wrote can reach the brief, and every number in the draft is checked against the data.

Every draft starts with a DRAFT marker. Only a person removes it, and only then is a brief published.

Ground rules

What Tripvane does not do

  • Decoy tools have no side effects. They log the call and return a plausible fake result. No email is sent, no file is read, no command runs.
  • Decoys cannot be used as a proxy. Their outbound traffic is limited to the model API and Tripvane's own collector.
  • Canary credentials are invalid everywhere. Realistic formats with a checksum only Tripvane can verify. No real key is planted anywhere.
  • Sources are recorded, never probed. Tripvane does not scan, attack back or contact the addresses it records.
  • Little is stored. At most the source IP address and network, a fixed subset of request headers, an account handle, the payload and the agent transcript.
  • Nothing is published automatically. Briefs wait for a person, and new tags wait for a person to add them to the taxonomy.

Early operation

Check a source before your agent trusts it

Tripvane is open source and in its first weeks of operation. Until the decoys have recorded more traffic, most lookups will answer not seen. Questions, API key requests and reports go to the issue tracker.
