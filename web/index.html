Deception grid for AI agents

Decoy agents that record what attackers ask them to do, and never do it.

Tripvane runs decoy AI agents on the open internet: a support chatbot, an MCP server, lookalikes of self-hosted LLM tools and a GitHub triage bot. When someone tries to steer one of them with a prompt injection, every tool call the agent attempts is recorded and answered with a fake result. Nothing runs.

What the decoys capture is classified, grouped into campaigns and published as a lookup of IP addresses, domains and payloads, so that people and agents can check a source before they trust it.

How it works

From a single injected message to a public record

  1. A decoy receives input

    Each decoy looks like an ordinary agent product with ordinary tools: send_email, read_file, list_secrets, run_shell, http_get and write_file, plus a few that fit its role.

  2. A cheap check runs first

    Input under eight characters, or a repeat of a recently accepted payload, never reaches a model. Each decoy has a daily token budget and a per-address rate limit, so a scanner cannot run up the bill.

  3. Tool calls are recorded, not run

    Every call becomes a tool_call_attempted event with its arguments and the static fake result the model was shown. Credentials planted in those results are canaries: realistic in shape, invalid everywhere.

  4. Events reach the collector

    Each event is written to disk on the decoy before it is shipped to an authenticated ingest endpoint, and stays there until the collector accepts it.

  5. The analyst classifies

    A small model decides whether an input tries to make an agent act against its operator. Attacks are tagged on three axes, and near-identical payloads are grouped into campaigns.

  6. Results are published

    A public lookup API and page, a feed for key holders, a Claude Code plugin, and a weekly brief that a person reviews before it goes out.

The decoys

Four kinds of agent an attacker would want to reach

The decoys present themselves as products of a fictional company and carry no Tripvane branding. Their addresses are not listed here.

Support chatbot

channel http

The help desk of a SaaS company, answered by a decoy agent with mail, file and secret-store tools.

MCP server

channel mcp

An internal operations server over streamable HTTP. Tool listings and every tools/call are recorded; customer and invoice lookups return fictional records.

LLM infrastructure lookalikes

channel http · no model

Static endpoints in the documented shapes of Ollama, Open WebUI, LiteLLM and Langflow. Every request is recorded and no tokens are spent.

GitHub triage bot

channel github

Reads new issues, comments and pull requests on a public repository. Its GitHub App has read-only permissions, and its labelling and commenting tools are decoys too.

Taxonomy

What a recorded attack is tagged with

The tagger assigns exactly one tag per axis. Payloads that fit no technique get a proposed new tag, and a person decides whether it joins the list.

technique

direct_instruction
Tells the agent openly to take an action.
role_override
Tries to replace the agent's instructions or identity.
hidden_in_document
Embedded in content the agent processes: a page, issue, email or diff.
tool_argument_injection
Arrives through a tool's arguments, description or result.
encoded
Obfuscated so that a text filter would miss it.
other
None of the above.

objective

exfiltrate_secrets
Reveal or send out credentials, keys or the system prompt.
send_message
Send a message the operator did not ask for.
destructive_action
Delete, overwrite or disable data or systems.
persistence
Leave something behind that keeps influence or access.
recon
Disclose tools, permissions, configuration or environment.
none
No objective beyond changing behaviour.

target_tool

email
Sends or reads email or other messages.
filesystem
Reads, writes, lists or deletes files.
shell
Runs commands or code.
http
Makes web requests or fetches URLs.
secrets
Holds credentials, keys or configuration secrets.
none
No specific tool.

Lookup

Has the grid seen it?

Try

Enter an IPv4 or IPv6 address, a domain, or the sha256 of a payload. The answer gives first and last sighting, how many decoys and sessions saw it, its most common tags and its campaign.

Not seen is not a clean bill of health. It means only that this grid has not recorded the value. New hosts and reworded text are unseen by definition.

Payloads are looked up by hash, so the text itself never has to leave your machine. The hash is taken after lowercasing, collapsing every run of whitespace to one space and trimming both ends.

Lookups are free: 50 a day per address, or 5,000 a day with an API key. Full lookup page · API reference

API and feed

Four endpoints, plain JSON

The lookups are public. The feed returns attack payloads from the last 24 hours with their tags and campaign ids, and needs a key sent as X-Api-Key. Keys are issued by hand while the grid is young; ask for one through the repository.

# public, 50 a day per address
GET /v1/lookup/ip/{ip}
GET /v1/lookup/domain/{domain}
GET /v1/lookup/payload/{sha256}

# with X-Api-Key, 5,000 a day
GET /v1/feed/recent

Claude Code plugin

Let your agent check before it trusts

The plugin gives Claude Code three lookup tools and a skill that tells it when to use them: before installing an MCP server from a host it has not seen, and whenever a document, issue or web page reads as instructions aimed at an agent.

It sends only the value being looked up. For text, that is the hash.

# in Claude Code
/plugin marketplace add TanmayKallakuri/TripVane
/plugin install tripvane@tripvane

When asked for the API URL, enter https://tripvane-api.vercel.app. An API key is optional. The plugin needs uv on your PATH.

Weekly brief

What the grid saw this week, checked by a person

Each week a model drafts a short brief from the period's aggregate figures. It never sees captured payload text, so nothing an attacker wrote can reach the brief, and every number in the draft is checked against the data.

Every draft starts with a DRAFT marker. Only a person removes it, and only then is a brief published.

Ground rules

What Tripvane does not do

  • Decoy tools have no side effects. They log the call and return a plausible fake result. No email is sent, no file is read, no command runs.
  • Decoys cannot be used as a proxy. Their outbound traffic is limited to the model API and Tripvane's own collector.
  • Canary credentials are invalid everywhere. They follow realistic formats with a checksum only Tripvane can verify. No real key is planted anywhere.
  • Sources are recorded, never probed. Tripvane does not scan, attack back or contact the addresses it records.
  • Little is stored. At most the source IP address and network, a fixed subset of request headers, an account handle, the payload and the agent transcript.
  • Nothing is published automatically. Briefs wait for a person, and new tags wait for a person to add them to the taxonomy.

Status

Early operation

Tripvane is open source and in its first weeks of operation. Until the decoys have recorded more traffic, most lookups will answer not seen.
